Kimi K3 benchmark · September 19, 2026

K3 is faster. Quality is the tradeoff.

Kimi K3 cut P50 latency to 5.22 seconds and P95 to 8.21 seconds on the ten-question benchmark. It passed nine questions, missing the transaction-year case, so it improves responsiveness without yet clearing either the accuracy or sub-three-second P50 gate.

Recommendation: continue K3 as a latency candidate, not as the production winner. Repair the general date-filtering weakness, verify prompt-cache behavior, and repeat the benchmark before comparing a K3 or K3 Fast path with the 10/10 K2.6 baseline.

05 / Decision

Promising candidate, not yet a winner

K3 moved the latency frontier in the right direction, but the quality regression and P50 miss prevent a production recommendation from this run.

Fix the general date rule

Explicitly require ISO calendar-year filters using strftime('%Y', date) or half-open date ranges, then validate on held-out date questions.

Recover quality gate

Repeat cache trials

Run cold and warm suites separately with five repetitions per question. Keep the K3 model/schema key fixed and report cache residency.

Make latency defensible

Evaluate K3 Fast

Benchmark accounts/fireworks/routers/kimi-k3-fast against the same execution checks. Its list price is 50% above standard K3.

Best K3 speed test

Test a fast-primary cascade

Return validated SQL from the fastest accurate model and reserve K2.6 or K3 for execution failures and ambiguity.
