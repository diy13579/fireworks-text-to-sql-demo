Cache-affinity benchmark · September 19, 2026

Caching works. Generation still sets the pace.

A deterministic prompt_cache_key raised prompt-cache reuse from 26.90% to 88.36% while preserving 10/10 execution accuracy. Mean and tail latency improved substantially, but P50 remained 7.27 seconds while median SQLite execution was only 2.403 milliseconds.

Decision: keep cache affinity because it improves cost, prefill work, and tail behavior. The remaining bottleneck is the remote model path, with completion volume strongly implicating Kimi K2.6 reasoning and generation rather than SQLite execution.

05 / Next

Keep caching. Reduce generation.

The next experiment should retain the cache key as infrastructure, while changing the model path that now controls latency.

Capture Fireworks server timing

Enable perf_metrics_in_response and persist server time to first token and total server processing time.

Record reasoning tokens

Persist completion_tokens_details.reasoning_tokens alongside total completion usage.

Explains long outputs

Benchmark a faster primary model

Use the same cache key, schema, questions, and quality gate with non-reasoning or lower-latency Fireworks models.
