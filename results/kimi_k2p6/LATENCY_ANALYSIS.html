Accuracy is ready. Latency is not.

Kimi K2.6 produced correct results for all ten development questions, but the median request took 14.28 seconds against a target below 3 seconds. Local SQL is not the limiting stage.

Primary bottleneck: the remote Fireworks generation path, including model inference, reasoning, and network time. It accounts for at least 99.0% of every measured request.

04 / Optimization

Optimize the remote path first

Keep execution accuracy as a hard gate. Every experiment should use the same ten questions plus repeated runs to expose variance.

Instrument model calls

Persist request count, queue/server timing if exposed, prompt tokens, reasoning tokens, output tokens, finish reason, truncation retry, SQL repair, and model name.

Enables true attribution

Benchmark faster serverless models

Compare non-reasoning or lower-latency structured-output models with Kimi using accuracy, P50, P95, cost, and truncation rate.

Largest likely gain

Add a fast-model cascade

Send each question to the fast model first. Escalate to Kimi only after validation failure or a low-confidence/ambiguous classification.

Target ≥80% fast path

Retrieve only relevant schema

Use deterministic table/column selection first, always preserving join edges and encoded-value documentation. Avoid an embedding network call for this eight-table schema.

Lower input and reasoning load

Cap tail latency

Replace the automatic 8,192-token retry in the interactive path with a deadline. Offer escalation explicitly or run it asynchronously instead of blocking the CLI.

Controls P95/P99

Optimize q_007 locally later

Store/index a normalized year column or use an index-friendly date range. This saves roughly 0.29s, useful only after model latency is reduced.

05 / Decision

Recommended architecture

The current single-model system is an accuracy baseline, not the final interactive architecture.

Proposed request path

Question + compact relevant schema → fast structured-output model
Validate read-only SQL → execute locally → return immediately on success
Escalate ambiguity, truncation, or execution failure → Kimi K2.6
Enforce request deadline → fail clearly instead of blocking for 30–120 seconds
